`runSchemaCli` now exits 1 and prints an "Unbekanntes Subcommand" error to
stderr for an unrecognized subcommand (e.g. a typo like `schema cutover`),
instead of silently printing the usage list and exiting 0. `kumiko schema`
with no subcommand at all is unaffected — that stays a help request (usage
on stdout, exit 0).

Previously any typo'd subcommand looked identical to a help request: usage
printed, exit 0. The shipped standalone app bin template
(`demo/bin/kumiko.ts`, generated by `scaffold-app.ts`'s `renderBinKumiko`)
delegates its `schema <sub>` argument straight into `runSchemaCli` and
exits with its return code — so a typo in a deploy script's migrate step
(`bun /app/kumiko.js schema <sub>`) would pass the step, print help, and
skip every migration without the deploy ever going red. (See
`packages/dev-server/CHANGELOG.md`'s "`migrate-step.sh.template` invoked
`bun /app/kumiko.js migrate apply`, but the CLI registers no `migrate`
command" entry for a prior instance of exactly this failure mode.)
