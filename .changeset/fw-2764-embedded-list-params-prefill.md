fw#2764: a `navigate` param now prefills an embedded-list field. `mergeSearchParamsIntoInitial` gained an embedded-list branch that reads the rows as JSON and runs every cell through the sub-schema's own coercion, so an actionForm reached from a row action opens with the existing rows instead of an empty grid — which mattered because a handler owning an embedded list replaces it whole, so a blank grid invited overwriting the rows it was meant to correct. Money cells keep their signed minor-unit-integer contract (the currency lives on the head aggregate, unlike a top-level money field's major-unit `{amount, currency}`), `select` cells are filtered against their declared options, and only sub-fields the author declared in `schema` are copied out of the param, so an undeclared key from the URL never reaches the form. A row list that isn't coercible — bad JSON, a non-array, a row that isn't an object, a cell the sub-schema rejects, or more rows than `maxItems` allows — leaves the field at its default and emits a dev warning instead of half-filling a list that would overwrite the rest on submit. An embedded list with no param now defaults to `[]` rather than `""`.
